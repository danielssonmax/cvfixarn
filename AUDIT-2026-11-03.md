# CVfixaren.se – full audit, 3 November 2026

Scope: security, SEO and internal linking, performance, conversion, legal/trust, design, and a first-time-visitor walkthrough of the whole funnel. Everything was read from the repository at commit `3ac27d1` and from a local build; production was only fetched with plain GET requests. No files were changed and no accounts, payments or emails were created.

How the work was done: I walked the site in a headless browser as a new visitor on a phone and a laptop (home → login → editor → download → paywall, plus every marketing page, the 404 page and the account pages), and three specialist reviewers went through the code for security, SEO/linking and performance. I re-verified every critical finding in the source before including it. File references are `path:line`.

## Scorecard

| Area | Verdict | One line |
|---|---|---|
| Security | **Critical** | Any visitor can read or overwrite any CV, export PDFs without paying, and cancelled subscribers keep premium forever. |
| Legal & trust | **Critical** | No privacy policy, terms that never mention the subscription, placeholder company details, a contact form that sends nothing, unverifiable claims. |
| Conversion (CRO) | Needs work | Strong hero and paywall; but the cookie backdrop blocks the first click, there is no mobile menu, the login button opens signup, and the price is a surprise at the end. |

## UX walkthrough as a first-time visitor (what I actually saw)

Method: headless Chrome against the local build, analytics hosts blocked, first visit with no cookies, on a 390×844 phone and a 1366×768 laptop. Screenshots are in the session scratchpad (`ux/` folder).

### Step 1 – Landing on the home page
- The page looks professional: clear headline, lime CTA, CV mock-ups, trust chips. The visual quality is good.
- **The cookie banner blocks the whole page on first visit.** It has a full-screen backdrop (`components/cookie-consent.tsx:280`, `fixed inset-0 bg-black/30 z-40`), so nothing is clickable until the visitor picks an option. Measured overlap with the hero button "Skapa ditt CV nu": 100 % on 390×844 and 430×932 phones and on a 1366×768 laptop, 36 % on 1536×864, 0 % on 1920×1080 – but on every size the backdrop intercepts the click. A visitor who ignores banners (most do) cannot start.
- "Skapa ett gratis CV – Var en av de 2 % som går vidare": the 2 % is never explained anywhere on the site. A sceptical visitor reads it as made up.
- Stats bar: "10 000+ CV:n skapade", "98 % nöjda användare", "15 expertgranskade mallar", "testade av rekryterare". None of these are sourced on the page. If they are not measured numbers, they are a Marknadsföringslagen risk and they also contradict the no-invented-statistics rule we applied to the content pages. The three testimonials (Tina V., Niklas S., Sara K.) with "fick flera intervjuer inom första veckan" need to be real, named customers who agreed to be quoted; fabricated reviews are on the EU/Swedish blacklist of unfair practices.
- Nothing above the fold says what it costs. The only price on the home page is inside FAQ item 2, far down. A visitor who reads "gratis" nine times on the page and then meets a 69 kr/week subscription at download time feels tricked (this is exactly the pattern Konsumentverket pursues with "gratis + prenumeration" services).
- On mobile there is **no navigation menu at all**: the nav links are `hidden lg:flex` in `components/header.tsx:65` and there is no hamburger. A phone visitor can only reach CV-mallar, CV-exempel, Skriva CV and Blogg through the footer, 36 screens down.

### Step 2 – "Logga in" in the header (returning visitor)
- Clicking "Logga in" opens a dialog titled **"Skapa ditt CV"** with the signup copy ("Ladda ned ditt CV som PDF, spara och redigera…"). `components/header.tsx:100-109` passes `mode="login"` to `SignupPopup`, but `SignupPopup` has no `mode` prop (`components/signup-popup.tsx:10-15`), so it always renders the signup form.
- Inside that dialog, the "Logga in" link calls `onClose()` and then `onOpenLogin()`, which only sets a state variable nothing reads (`components/header.tsx:123`). Result: clicking "Logga in" closes the dialog. The same happens on /profil. Technically the email field still works for existing users (it falls back to a magic link), but the screen says "Skapa ditt CV", which is the opposite of what the visitor asked for.

### Step 3 – The editor (/profil/skapa-cv)
- Good: the form is on the left, live preview on the right, a completion bar, the "Har du redan ett CV?" import box, a clear lime "Ladda ned" button. On mobile the preview is behind a "Förhandsgranska" button and opens a full-screen preview with a template carousel – this is well done.
- The preview starts as an empty white page with the heading "Curriculum Vitae". A first-time user gets no sense of what the finished CV will look like until they have typed a lot. Showing ghost/sample content (like the "Anders Andersson" mock-up on the home page) that is replaced as fields are filled would make the empty state motivating.
- The back button is labelled "Mina CV", but for an anonymous visitor it leads to a page saying "Logga in för att se dina sparade CV:n" – a dead end. Label it "Tillbaka"/"Startsidan" until the user has an account.
- Home page says "Ladda ner", the editor says "Ladda ned", the paywall says "Ladda ner". Pick one.
- Every fresh visit fires `GET /api/load-cv?id=<new uuid>` which returns 404 (seen in the console on both desktop and mobile). Harmless, but it is a wasted request and a red error in the console on every visit.
- Clicking "Fler fält" (and some other changes) unmounts the preview and shows "Laddar CV preview…" for a second or more. Each remount is a full iframe reload.
- Five icon-only buttons in the editor have no accessible name (the rich-text toolbar and the full-screen toggle), and the page contains two `<main>` elements and two `<h1>`s.

### Step 4 – Clicking "Ladda ned" without an account
- A dialog "Skapa ditt CV" asks only for an email. It lists "Ladda ned som PDF", "Spara och redigera", "Välj mellan flera mallar" and says "Genom att fortsätta godkänner du våra villkor" with no link to the terms. **There is no mention of the trial or the 69 kr/week price at this step.**
- The account is created immediately with a random password (`components/signup-popup.tsx:49`), so the visitor is now a registered user before knowing the price.

### Step 5 – The paywall ("Steg 2 av 2 · Bekräfta medlemskap")
- This dialog is honest and well written: "0 kr för 7 dagar", "Därefter 69 kr/vecka · ingen bindningstid", fine print about renewal. Good.
- The payment-method logos are hot-linked from wikimedia.org and 1000logos.net (`components/capture-payment.tsx:81-103`). If either host changes or blocks hot-linking the paywall shows broken images at the exact moment of purchase. Put the four SVGs in `/public`.
- "Fortsätt utan erbjudande" is the only way out; after it the user is logged in with no way to get any version of their CV (no watermarked preview, no print). That is a business choice, but it is worth knowing that the user now has an account, has typed a whole CV and leaves with nothing – the abandoned-cart email is the only follow-up.

### Step 6 – Logging in later via the magic link
- Every magic-link login lands on `/profil/skapa-cv?new=true&pay=true` (`app/auth/callback/route.ts:50`). `new=true` starts a brand-new empty CV and `pay=true` opens the paywall immediately (`app/profil/skapa-cv/CVMallClient.tsx:130-148`). So a returning free user who clicks "Logga in" to continue their saved CV gets: an empty editor plus the "Starta din gratisvecka" dialog before seeing anything. This is the same "popup on arrival" behaviour you asked me to remove from the header button, still present on the login path. Returning subscribers are spared only because the server check runs first.

### Step 7 – Account page and cancelling
- `/profil/konto` says **"Du kan avsluta ditt medlemskap 48 timmar efter registrering"** and hides the cancel button for 48 h (`app/profil/konto/page.tsx:56-61, 134-147`). The trial is 7 days, so this does not protect revenue, but it is the kind of friction Konsumentverket calls out ("lika lätt att säga upp som att ingå"), and it generates support mail and chargebacks. Remove the 48 h gate.
- The cancel button is a generic Stripe billing-portal login link; the customer has to enter their email and get a one-time code. A server-created portal session (`stripe.billingPortal.sessions.create`) would open the portal already logged in.

### Step 8 – Contact page
- The address "Storgatan 1, 123 45 Stockholm" and the phone "08-123 45 67" are placeholder values (`app/kontakt/page.tsx:45-51`). Someone will call that number.
- **The contact form does nothing.** `app/kontakt/page.tsx:57` is a `<form>` with no `action` or `onSubmit` (`components/KontaktPage.tsx` is an unused copy with the same bug); pressing "Skicka meddelande" reloads the page with the name, email and message appended to the URL as query parameters, and nothing is sent. Every support request written there since launch has been lost. Either wire it to Resend (`/api/contact`) or replace it with a mailto link to support@cvfixaren.se.

### Step 9 – Wrong URL (404)
- The 404 page is **blank**: the default Next.js "404 – This page could not be found" renders with white text on a white background (computed colour `rgb(255,255,255)`, verified in the browser) because the site's base styles override the inline styles. There is no `app/not-found.tsx`, `app/error.tsx` or `app/global-error.tsx`. A visitor who mistypes a URL or follows an old link sees an empty white page.

### Pages that should not exist in production
- `/app` (`app/app/page.tsx`) is a v0 mock-up that shows fake saved CVs ("My First CV", "Software Developer CV") to anyone, with no title and no noindex. Live in production (HTTP 200).
- `/testconversion` is a test page for the purchase dialog. Live in production (HTTP 200).
- `/app/cv-mall`, `/resumes/[id]/edit` look like leftovers too.
## Legal and trust (this is where the real business risk is)

I am not a lawyer; these are the points a consumer-law review would raise first, and they match the pattern Konsumentverket keeps acting on ("gratis" services that turn into subscriptions, hard-to-cancel memberships). Have a Swedish consumer-law practitioner confirm the fixes.

**L1. There is no privacy policy.** No `integritetspolicy` route exists, yet the FAQ (`app/vanliga-fragor/page.tsx:46` "se vår integritetspolicy"), the marketing policy (`app/marknadsforing/page.tsx:42`) and the download dialog ("användarvillkor och sekretesspolicy") all refer to one, and the cookie banner has no link to any policy. GDPR art. 13 requires this information at the point of collection (signup, contact form, CV data). CV data is sensitive-adjacent personal data (addresses, employment history, photos). Write one page covering: controller identity, what is stored (CVs, email, gclid/referrer, Stripe customer id), processors (Supabase, Stripe, Resend, Vercel, Google, the LinkedIn-scraping API, Anthropic for the CV optimiser), retention, rights, cookies. Link it from the footer, the cookie banner, the signup dialog and the FAQ.

**L2. The terms do not describe the product you sell.** `app/anvandarvillkor/page.tsx` has six short sections (use of the service, user content, IP, liability, changes, contact) and not one word about the subscription: no price, no trial, no renewal interval, no cancellation method, no ångerrätt (14-day withdrawal right under distansavtalslagen, and the information the trader must give before the contract; if that information is missing the withdrawal window extends up to a year), no mention of the consumer's consent to start the service before the withdrawal period ends. The Stripe checkout is the only place the price is shown, and the signup dialog says "Genom att fortsätta godkänner du våra villkor" without linking to them. Add a "Medlemskap och betalning" section, link the terms from both dialogs, and enable `consent_collection.terms_of_service` in the checkout session so Stripe records acceptance.

**L3. Placeholder company details on the contact page.** "CVfixaren AB, Storgatan 1, 123 45 Stockholm, 08-123 45 67" (`app/kontakt/page.tsx:45-51`) are template values. E-handelslagen requires the trader's real name, address, e-mail and organisationsnummer. Put the real details (or remove the address/phone and keep the email) and add the org number to the footer.

**L4. The contact form sends nothing** (see UX step 8). Besides losing customer mail, the submitted name, email and message end up in the URL query string and therefore in logs and analytics.

**L5. "Gratis" nine times on the home page, 69 kr/week to get the file.** Konsumentverket's position on "gratis": a product may not be marketed as free when the consumer has to pay for anything beyond the unavoidable cost of responding (blacklist point 20 of the unfair-practices list implemented in Marknadsföringslagen). "Skapa ett gratis CV" is defensible (creating is free) but the title tag, the H1, the hero button and the final CTA ("det är gratis att börja") together create the expectation that the CV is free, and the first time the visitor learns otherwise is after they have typed their whole CV and created an account. Safer and, in my experience, better-converting wording: "Prova gratis i 7 dagar", "Skapa ditt CV – ladda ner som PDF, 0 kr första veckan". Put the price on the home page (a small "Så funkar priset" block near the FAQ) and on a `/priser` page.

**L6. The 48-hour cancellation block** (`app/profil/konto/page.tsx:56-61`). Cancelling must be at least as easy as signing up; a timed lock on the cancel button is the kind of friction that produces complaints to Konsumentverket and chargebacks. Remove it.

**L7. Unsourced numbers and reviews.** "Var en av de 2 % som går vidare", "10 000+ CV:n skapade", "98 % nöjda användare", "15 expertgranskade mallar", "testade av rekryterare", "Upp till 75 % av alla CV:n avvisas av ATS" (FAQ and `/ats-anpassade-cv-mallar`), three named testimonials. Every one of these must be true and provable, or removed. If the testimonials are real customers, keep records of consent; if they were written in-house, delete them – fabricated reviews are explicitly banned since the 2022 consumer-law update. The 75 % ATS figure is a 2012 vendor marketing claim that has never been substantiated; drop it.

**L8. The FAQ promises "All information du anger krypteras" and "Vi delar aldrig dina personuppgifter med tredje part utan ditt samtycke".** CV data is shared with processors (Supabase, Stripe, Resend, Vercel, the LinkedIn API, Anthropic if the optimiser is enabled). That is normal and legal under a processor agreement, but the sentence as written is false. Reword to "Vi delar bara uppgifter med de leverantörer som behövs för att driva tjänsten, se integritetspolicyn".

**L9. Example CVs with realistic contact data.** The eight hand-written examples in `lib/cv-examples.ts` use addresses such as `markuseriksson@gmail.com`, `hakan_strom@gmail.com`, `liam.persson98@live.se`, `mario.pausini@telia.se` and phone numbers like `073-5502505`. These can belong to real people. Switch them to `@example.com` and the reserved `070-174 06 xx` range, as the newer examples already do.

**L10. The SoftwareApplication schema advertises `price: 0`** (`app/page.tsx:206-210`). Google treats structured data that contradicts the page as spammy markup. Either describe the trial/subscription in `offers` or remove the price.

## Conversion (CRO)

What converts today: a strong, clean hero; the lime CTA is unmissable; the editor is fast to start (no signup wall), the completion bar and the "upload your old CV" box lower effort; the paywall dialog is honest and well designed; abandoned-CV emails exist.

What is leaking conversions, in order of expected impact:

1. **The cookie backdrop blocks the first click on every device** and physically covers the hero CTA on phones and 1366-px laptops. Make the banner a non-blocking bottom bar without a backdrop, keep "Neka" and "Acceptera" equally prominent, and never cover the primary CTA.
2. **No mobile navigation.** Phone visitors (the majority for job seekers) cannot reach templates, examples or the guide from the header. Add a hamburger menu with the four nav items, "Personligt brev", "Priser" and "Logga in".
3. **Price surprise at the end of the funnel.** Visitors invest 10-20 minutes typing, then hit signup, then the paywall. Telling them earlier ("0 kr i 7 dagar, sedan 69 kr/vecka, avsluta när du vill" under the hero CTA and in the signup dialog) costs a few top-of-funnel clicks and wins back the trust that drives trial starts, lowers chargebacks and removes the duplicate-subscription confusion you saw earlier.
4. **No pricing page.** "cvfixaren pris", "cvfixaren kostnad", "cvfixaren gratis" are the questions people google before trusting a CV service; a `/priser` page with the trial terms, what is included, how to cancel, and a FAQ catches that search and reassures.
5. **The login button opens the signup dialog** (bug, UX step 2). Returning users who want their saved CV are the warmest traffic you have.
6. **Magic-link login lands on an empty new CV with the paywall open** (UX step 6). Send logins to `/profil` (their CV list) and keep `pay=true` only for the post-signup and reminder-email paths.
7. **Empty preview in the editor.** Ghost content in the preview (grey sample text that disappears as fields are filled) shows the value before the work.
8. **The 48-hour cancel lock and the generic Stripe portal link** create support load; a one-click portal session from the account page is both the legal expectation and cheaper.
9. **Trust signals are weak where they matter:** the paywall has hot-linked card logos, no "avsluta med ett klick" line, and no link to terms. The home page stats cannot be verified. Replace invented numbers with things you can prove (e.g. real CV count from the database, "Svenskt företag, support på svenska", a real org number in the footer).
10. **Broken 404 and dead contact form** are small on their own, but each one is a visitor who concludes the site is abandoned.
11. **After "Fortsätt utan erbjudande"** the user has typed a full CV and leaves with nothing. Consider a low-cost intermediate: a watermarked preview image, a "mejla mig en påminnelse" button, or a 1-day pass. At minimum make sure the reminder email reaches them (it does, via the cron, if their CV is at least a few hours old).

## Overall look and design

The marketing site looks like a current, well-made product: consistent spacing, a real type system (Plus Jakarta Sans), the navy/green/lime palette holds together, cards and chips are restrained, and the editor's dark preview canvas with the light form reads as "a tool", not a template. The template picker, the mobile preview sheet and the completion bar are better than most Swedish competitors.

Things that look unfinished to a careful eye:
- The 404 page is blank and the contact page has dummy address data (both read as "abandoned site").
- The `/cv-exempel` hub uses a clip-art businessman next to a real CV mock-up; it is the one dated element on the site.
- The signup dialog and the paywall are good, but the small "Logga in" dialog bug and the "Mina CV" dead end break the illusion of polish right at the moment of commitment.
- Cookie banner copy ("vidarebefordrar identifierare till sociala medier") is boilerplate that does not match what the site does (there are no social widgets); it undermines the otherwise clean tone.
- Editor icon buttons without labels, two `<h1>`s, no skip link: accessibility is decent (labels on inputs, alt text everywhere, visible focus ring) but not finished.
- Wording drift: "Ladda ner" vs "Ladda ned"; "medlemskap" (account page, checkout title) vs "prenumeration" (paywall fine print) vs "provperiod" (FAQ). Pick one vocabulary for the subscription.
## Security

I had a reviewer read every API route, the auth flow, the Stripe/Supabase code, the SQL policies and the headers, and I re-checked the critical items in the code myself. Only read-only GET probes were sent to the local server; nothing was written to the production database or Stripe.

### Critical (fix this week)

**S1. Anyone can overwrite or inject CVs into any account – `/api/save-cv` trusts a client-supplied user id.** Verified.
`app/api/save-cv/route.ts:13-35`: `let userId = user_id` comes straight from the JSON body; the bearer token is only checked `if (token && !userId)`. A request with no login and `{ "user_id": "<victim>", "id": "<victim cv>", "data": {...} }` updates the victim's CV, and without `id` it inserts a new CV into their account. Combined with S3, the injected CV can carry script that runs when the victim opens /profil.
Fix: ignore `user_id` from the body, always derive the user from the verified token (`getUserIdFromRequest` in `lib/subscription.ts` already does this), return 401 without it, and validate `data` with the `cvDataSchema` that already exists in `lib/validations.ts` but is never used.

**S2. Anyone can read any CV, including name, address, phone and the owner's user id – `/api/load-cv` has no authentication.** Verified (a GET with a random id answered 404, not 401).
`app/api/load-cv/route.ts:7-35` uses the service-role key and filters only on the CV id; `user_id` is an optional query parameter the caller chooses. CV ids are UUIDs, so they are not guessable, but they appear in Stripe return URLs, reminder emails and browser history, and S1 lets an attacker plant one.
Fix: require the bearer token and always filter on the server-derived user id.

**S3. Stored and reflected XSS in the CV renderer.** Verified by code trace.
`lib/generate-cv-html.ts` (and the four other generators) interpolate name, title, email, phone and section titles into HTML without escaping; the result is injected with `dangerouslySetInnerHTML` in `components/resume-preview.tsx`, `components/cv-thumbnail.tsx` and `app/print/page.tsx`. `/print` also accepts `?data=` in the URL, so a crafted link executes script on your domain. The CSP allows `'unsafe-inline'`, so it does not help. `lib/sanitize.ts` is a regex sanitizer whose allow-lists are never applied (`onerror=alert(1)` without quotes passes).
Fix: escape every interpolation in the generators (`escapeHtml`), sanitise rich-text fields with DOMPurify (`isomorphic-dompurify`), remove the `?data=` path on `/print`.

**S4. The PDF export is free for anyone and can run up your Vercel bill – `/api/export-pdf` has no auth and no premium check.** Verified.
`app/api/export-pdf/route.ts:24+` accepts any CV JSON and launches headless Chromium (3 GB, 60 s per call per `vercel.json`). The only paywall is in the browser (`components/resume-editor.tsx:2252-2267`). A curl loop exports the product for free or burns compute.
Fix: verify the token, check `getSubscriptionStatus(userId).subscribed`, return 402 otherwise, rate-limit per user, and render the CV by id from the database rather than from the request body.

**S5. Premium is never taken away. Every customer who cancels keeps lifetime access.** Verified.
`app/api/webhooks/stripe/route.ts:59-84` handles only `checkout.session.completed` and sets `premium: "true"`. There is no handler for `customer.subscription.deleted`, `customer.subscription.updated` or `invoice.payment_failed`, and nothing in the code base ever writes `premium: "false"` except when a row is first created. `lib/subscription.ts:42-44` returns `subscribed: true` as soon as the flag is set, so the Stripe cross-check never runs for those users. In practice: start the 7-day trial, cancel on day 1, download PDFs forever. Everyone who has ever churned still has full access today.
Fix: handle `customer.subscription.updated/deleted` and `invoice.payment_failed` and set the flag to false when the status is not trialing/active/past_due; store `stripe_customer_id` and `stripe_subscription_id` on the `premium` row; re-verify flagged users against Stripe (cached daily). Reuse the Stripe customer so Stripe's one-trial-per-customer rule applies. The live webhook endpoint also still needs to be re-enabled in Stripe (open from the earlier session).

### High

**S6. Unauthenticated routes that cost money.** `/api/optimize-cv` (Claude Opus, 16 000 output tokens, 120 s, no login, no rate limit, uncapped description/skills strings), `/api/import-linkedin` (paid iScraper call per request; also returns `_debug.raw_linkedin_data` and console-logs the whole profile), `/api/import-cv` (5 MB PDF parsing per anonymous call), `/api/create-checkout-session`, `/api/checkout-session`, `/api/create-payment-intent` and the legacy server action in `app/actions/stripe.ts`. Fix: bearer auth on all of them, Upstash limits keyed on user id + IP, cap string lengths, delete the debug output and PII logging.

**S7. The rate limiter fails open.** `lib/rate-limit.ts:14-35` falls back to `new Map()` as the Redis client, which Upstash's `Ratelimit` cannot use (it throws), and the `catch` at `:72-80` returns `success: true`. With Upstash configured it works; if the env vars are missing or Upstash has an outage, `/api/login`, `/api/register` and `/api/create-payment-intent` (the only three routes that use it) have no limit at all. Fix: fail closed, or use a real in-process token bucket as the fallback, and assert the Upstash variables at startup in production.

### Medium

**S8. Email squatting on the `premium` table.** `/api/create-user`, `/api/signup` and `/api/register` insert rows with a client-supplied uid and email using the service role. `uid` and `email` are UNIQUE, so `{uid: random, email: victim}` prevents the victim's real row from ever being created (the upserts in `auth/callback`, `register` and the webhook collide on `email` and the errors are swallowed) – a paying customer would never become premium. `/api/check-premium?email=` is an unauthenticated "is this email premium" oracle with no callers. Fix: delete `create-user`, `signup` and `check-premium`; in `register` take uid and email from the verified token only.

**S9. `/api/create-checkout-session` leaks the account email for any user id** (`route.ts:26-48`, no auth; the email is put into `customer_email` of the returned checkout). Fix: derive the user from the token.

**S10. Headers and third-party script.** CSP has `'unsafe-inline'`, `'unsafe-eval'`, `img-src https:` and `https://unpkg.com`; no `frame-ancestors`, `object-src`, `base-uri`, `form-action` or `Permissions-Policy`; HSTS without `preload`. `unpkg.com` is there only to load `pagedjs/dist/paged.polyfill.js` unpinned and without SRI (`app/print/page.tsx:1005`, `components/PrintPreviewIframe.tsx:283`) – that script runs in every user's browser and inside your server-side Chromium. Fix: `npm i pagedjs@<version>` and serve it from `/public`, drop `unpkg.com`, add the missing directives, remove `'unsafe-eval'`.

**S11. Information disclosure.** Raw database and Stripe error messages are returned to clients in `load-cv`, `save-cv`, `delete-cv`, `get-user-cvs`, `sync-cv`, `create-checkout-session` and `export-pdf`; `/api/whoami` is a debug route in production; `lib/security-logger.ts:103-111` console-logs email + IP + user id on every auth and payment event (these end up in Vercel logs). Fix: generic error bodies, log server-side only, delete `whoami`.

### Findings, ranked

**P1. Google Ads tag loaded twice, with high priority.** `app/layout.tsx:56-65` loads `gtag/js?id=AW-16880470708` (167 KB) in addition to the GTM container `GTM-KSFMWF8M` (`layout.tsx:47-53`). The container already carries the Google tag `GT-NMCR96NR` (verified in the fetched container). If AW-16880470708 is a destination of that Google tag (check in GTM → Google tag → Destinations), the standalone loader is pure duplication and also explains why purchase conversions were at risk of double counting. Because it is a `next/script` in `<head>`, Next also emits a `<link rel="preload">` for it, so 167 KB of ad script competes with the hero image and fonts. Fix: remove the standalone loader and `gtag('config')`, send conversions via `dataLayer` events to a GTM conversion tag.

**P2. GTM is injected `beforeInteractive`** (`layout.tsx:47`): the 158 KB container starts downloading at parse time, ahead of React hydration. Keep the small consent-default snippet inline and load GTM `afterInteractive`.

**P3. Blog posts are rendered on every request.** `app/blogg/[slug]/page.tsx` has no `generateStaticParams`, so every blog view is a serverless invocation with `Cache-Control: private, no-store` (737 ms vs 134 ms for static pages) and the HTML does not even get the font preloads. Add `generateStaticParams()` returning `Object.keys(blogPosts)` and `export const dynamicParams = false`, exactly as `app/cv-exempel/[slug]/page.tsx:19-23` does. One-line fix with a large effect on your most-linked SEO pages.

**P4. Middleware runs on everything.** `middleware.ts:12-14` only excludes `_next/static`, `_next/image` and `favicon.ico`, so every HTML page, every `/images/*.png`, `/robots.txt`, `/sitemap.xml` and every link prefetch (`?_rsc=`) goes through a 66 KB edge function that parses cookies and may refresh a Supabase session. One home-page view is roughly 20-35 edge invocations. The marketing pages never read the session server-side, so this is cost and latency for nothing. Restrict the matcher to `/profil/:path*` and the few API routes that need cookie refresh.

**P5. The editor ships dead and eager code.** `html2canvas` and `jspdf` (124 KB compressed) are imported in `app/profil/skapa-cv/CVMallClient.tsx:18-19` for a `downloadPDF()` that nothing calls (the real export is `fetch('/api/export-pdf')`). Stripe.js (266 KB) is loaded at module scope (`CVMallClient.tsx:23-25`, `components/stripe-checkout-dialog.tsx:10-12`) on every editor visit although only paying visitors need it; `lib/stripe-client.ts:12` already has a lazy getter. Tiptap, dnd-kit and the popups are never code-split (`next/dynamic` is used once in the whole app). `@react-pdf/renderer` is imported in `components/resume-editor.tsx:94-95` and never used.

**P6. Images are served unoptimised.** `next.config.mjs:9-11` sets `images.unoptimized: true`, so `next/image` emits plain `<img>` with no srcset and no WebP/AVIF; every `sizes` attribute on the site is dead. The template thumbnails are 740×1024 JPEGs displayed at 255-320 px (2-3× oversized); `/cv-mallar` sends 806 KB of images and lazy-loads even the first row. `/public` assets are served with `max-age=0, must-revalidate`, so every repeat visit re-validates every image. Fix: remove `unoptimized` (Vercel image optimisation) or pre-generate 360/720 px WebP variants; add `Cache-Control: public, max-age=86400, s-maxage=31536000, stale-while-revalidate` for `/images/:path*` in `next.config.mjs` `headers()`; eager-load the first row on `/cv-mallar`.

**P7. Third-host logos on the critical path.** The header logo (`components/header.tsx:57`, `priority`, so it is preloaded) and footer logo come from `hebbkx1anhila5yf.public.blob.vercel-storage.com` with no preconnect: an extra DNS + TLS handshake before the logo appears, on every page. Move both files to `/public`.

**P8. Fonts.** `latin-ext` is requested in addition to `latin` (`layout.tsx:12-17`), preloading a second 22 KB font file on every page; å, ä and ö are in the `latin` subset. The editor preview injects six Google-Fonts `@import`s (`components/resume-preview.tsx:361-368`, also `cv-thumbnail.tsx`, `app/print/page.tsx`) with no preconnect: six render-blocking CSS requests on editor load. Load only the selected font, or self-host the six families.

**P9. The PDF export is slower and noisier than it needs to be.** `/api/export-pdf` boots Chromium, opens `/print` and waits for `networkidle0`; `/print` sits under the root layout so the headless browser downloads GTM, gtag and Vercel Analytics on every export (phantom page views from your Lambda in Analytics) and pulls `paged.polyfill.js` from unpkg (~130 KB compressed). Give `/print` its own layout without the tag scripts, self-host paged.js, wait for `domcontentloaded` plus the existing `waitForFunction`.

**P10. Editor render pipeline.** `useWatch` on the whole form (`components/resume-editor.tsx:1580`) re-renders the entire 3 420-line component on every keystroke; `PreviewBridge.tsx` watches the whole form again with a 1 s debounce; `resume-preview.tsx:102-349` renders a hidden copy, waits 100 ms, measures every section with `offsetHeight` (forced layout) and rewrites pages via innerHTML. Autosave fires 800 ms after each pause with `auth.getSession()` + `POST /api/save-cv` (select + update with a title-retry loop); anonymous drafts stringify the whole CV including the base64 photo into localStorage on every pause. On long CVs and mid-range phones this is the INP risk. Fixes: subscribe to the fields each panel needs, paginate in `requestAnimationFrame`/`ResizeObserver`, raise the autosave delay to ~2 s, keep the photo out of the localStorage draft.

**P11. Structured data is injected client-side.** All JSON-LD on the site is rendered through `next/script` (`app/page.tsx:174-270`, `app/cv-mallar/page.tsx`, `components/breadcrumbs.tsx`, the example pages). Verified on production: the server HTML contains **zero** `<script type="application/ld+json">` tags; the schema only exists as serialised props inside the React flight data and is created by JavaScript after hydration. Googlebot usually renders JS and will often still pick it up, but it is delayed and unreliable, and Bing, AI crawlers and the Rich Results "fetched HTML" view do not see it. Use a plain `<script type="application/ld+json" dangerouslySetInnerHTML={...} />` in the server components instead of `next/script`.

**P12. Small layout shifts.** `/cv-exempel` declares 1024×640 for a 1600×1040 hero image (`app/cv-exempel/page.tsx:295-296`); the blog infographic has `height="auto"` (`app/blogg/[slug]/page.tsx:1125`); logged-in users see the header button cluster swap after `checkAuthStatus()`; the glass header's `backdrop-filter: blur(14px)` costs repaint on low-end phones.

**P13. Legacy routes are still built and shipped:** `/app/cv-mall` (388 KB, a second copy of the editor), `/app`, `/resumes/[id]/edit` (377 KB), `components/PrintPreviewIframe.tsx` (unused, loads unpkg), `app/sitemap.xml/route.ts` (shadowed by `app/sitemap.ts`; the served sitemap is the 37-URL data-driven one), unused `lodash` and `recharts` dependencies.

Remove the standalone gtag loader (after confirming the GTM destination) · GTM → `afterInteractive` · `generateStaticParams` on the blog · restrict the middleware matcher · delete html2canvas/jspdf/@react-pdf imports and the dead download code · lazy `loadStripe` · drop `latin-ext` · move the two logos to `/public` · Cache-Control for `/images/*` · eager-load the first template row · fix the two image dimension bugs · JSON-LD as plain script tags · delete the legacy routes and the duplicate sitemap route.
